# 28. Glossary and source index

**Baseline:** `60143d8f59`.
This chapter resolves names that are easy to confuse and indexes the shell-manual-relevant implementation, tests, build files, and design documents. It is intentionally not an index of every repository file; adjacent service suites such as `OutputViewTest`, `WizardRegistryTest`, and `CssTokensTest` are outside this subset.

## 28.1 Glossary and confusing API pairs

| Term/pair | Meaning in this baseline |
|---|---|
| **CJAP** | The nbfx platform delivery, not a separate runtime or product. |
| **AppShell** | The platform application framework: shell, docking, windows, content, chrome, and lifecycle services. |
| **`ShellApplication` vs `ShellRuntime`** | `ShellApplication` exists and is the current composition root. `ShellRuntime` is target only and does not exist here. |
| **`DockRuntime` vs `Docking`** | `DockRuntime` is the instance-owned implementation of the main dock area. `Docking` is the Legacy static facade that delegates to the most recently created runtime. |
| **`ShellRegion` vs `ViewArea`** | A shell region is window chrome (brand/menu/toolbar/dock/status/overlay). A `ViewArea` is a logical content-layout area. They are different models. |
| **`ShellRegionId` vs `ShellRegionKind`** | Id identifies a declared slot; kind selects renderer/ownership behavior. DOCK ownership is based on kind, not id. |
| **`PaneRole` in `api.shell`** | Legacy physical pane role: `MAIN`, `NAVIGATOR`, `DOCKED`, `DETACHED`, `SLIDE`. |
| **`PaneRole` in `api.layout`** | Target logical area identity: neutral `MAIN`, `SIDE`, `BOTTOM`, `CENTER`, plus product-defined namespaced roles. |
| **`ViewArea` in `api.views`** | Legacy lightweight area (`id`, display name, location, weight) used by the live dock. |
| **`ViewArea` in `api.layout`** | Pure CJAP logical area with kind, presentation, capabilities, policy, style, visibility, empty policy, and order. |
| **`DockGroupId`** | Stable physical group identity. In the baseline it is attached to an `NbfxTabPane`; it is not a tab id. |
| **`ContentId`** | Stable content identity. `WindowManager` uses it instead of `Tab` objects. |
| **`WindowId`** | Stable shell-window identity. Main is `nbfx:window.main`; custom ids are product-supplied. |
| **`DockLocation`** | `org.netbeans.api.nbfx.views.DockLocation` is the Legacy live-dock routing enum (`LEFT`, `LEFT_BOTTOM`, `CENTER`, `CENTER_BOTTOM`, `BOTTOM`, `RIGHT`). `org.netbeans.api.nbfx.layout.DockLocation` is the pure layout routing enum (`CENTER`, `START`, `END`, `TOP`, `BOTTOM`). |
| **`DockSide`** | Pure layout-tree side (`START`, `END`, `TOP`, `BOTTOM`, `CENTER`) used by `LayoutNode.Slot`. |
| **`DockPlacement`** | Transfer operation such as `INTO_GROUP`, `BEFORE`, `SPLIT_LEFT`, `EDGE_RIGHT`, or `FLOAT`. |
| **`DockRequest` vs `DropRequest`** | Dock requests move internal content/groups. Drop requests evaluate external/domain transfer sources against drop targets. |
| **`DockDecision` vs `DropDecision`** | Both carry acceptance and reason keys. Dock decisions refine placement; drop decisions also carry transfer effect. |
| **`TransferMode` vs `DockModifier`** | Transfer mode is MOVE/COPY/LINK and is used by drop decisions. Dock modifiers are COPY/FLOAT/NEW_WINDOW, but the baseline dock runtime does not interpret them. |
| **`WindowManager`** | Public docking/window operation surface over stable content/group/window handles. |
| **`WindowSystem`** | Lifecycle and persistence orchestration: init/load/show/hide/save/reset plus sink/listener seam. It is not NetBeans' Swing `WindowSystem`. |
| **`ShellWindow`** | Facade for the primary shell window; currently exposes concrete JavaFX stage/root/tab-pane types. |
| **`DockWindow`** | Handle for a main, floating, or custom shell window with show/hide/close/state operations. |
| **`WindowContent` vs `Content`** | `WindowContent` is a product-owned root/lookup/state host. `Content` is managed runtime content with close/dispose and a stable Node. |
| **`ContentManager` in `api.content`** | Per-shell generic owner of ready-made content close/dispose and active content. |
| **`ContentManager` in `api.editor`** | Legacy editor/file opening service used by `SessionRestorer` and shell integration. |
| **`ContentState`** | Opaque recreation payload keyed by `ContentId` and instance key. |
| **`WindowContentState`** | Opaque state saved by a `WindowContent`; includes window id, optional layout, and payload. |
| **`WindowState`** | Baseline whole-main-window/view snapshot. Target meaning is one window's groups/content/geometry/profile state. |
| **`SessionState`** | Target all-windows-plus-active-window snapshot. Absent in this baseline. |
| **`ViewStateStore`** | Baseline preferences store for `WindowState`/`AreaState` and view payload strings. |
| **`ContentStateStore`** | Baseline per-content payload store; implemented and tested but not wired into the shell. |
| **`WindowStateStore`** | Target owner of `SessionState`. Absent in this baseline. |
| **`LayoutSpec`** | Immutable, content-free CJAP layout: areas, groups, root tree, metadata, format version. |
| **`LayoutNode`** | Sealed pure tree node: `Split`, `Group`, or `Slot`. |
| **`DockTree`** | Legacy live-dock shape with permanent-role/docked leaves and a compact text form. Not `LayoutSpec`. |
| **`LayoutRegistry` vs `WindowLayoutRegistry`** | `LayoutRegistry` reads pure `NbFx/Layouts`/`LayoutAreas`/`DockGroups`. `WindowLayoutRegistry` reads Legacy `NbFx/WindowLayouts` used by the live dock. |
| **`ShellFrame` vs `ShellChrome`** | `ShellFrame` is the current root/dock/region-host adapter. `ShellChrome` is the Legacy top/bottom node contribution. |
| **`ShellProvider` vs `ShellChromeProvider`** | `ShellProvider` creates a complete frame and is the target direction. `ShellChromeProvider` is Legacy and priority-based. |
| **`ShellChromeProfile`** | Predicate-based profile interface with inclusive defaults; legacy implementations default to id `main`. |
| **`ShellProfileSpec`** | Immutable declarative profile with window kind, region allow-list, decoration, and system-menu-bar flag. |
| **`ChromeProfilePolicy`** | Product defaults by window kind plus fallback profile id. It is not itself a profile. |
| **`ShellProfileHint`** | Lookup capability requesting a profile id from content/group context. |
| **`ShellRegionHost`** | Runtime-owned mount/update/dispose lifecycle with stable wrappers. |
| **`ShellRegionRenderer`** | Creates visual content for a region kind. It is not a Node contribution registration. |
| **`ShellContribution`** | Product Node factory instantiated freshly per shell mount and disposed by the host. |
| **`@ActionRegistration` vs `@ActionReference`** | Registration defines behavior once under `NbFx/Actions`; reference places that action on a surface under `.ref`. |
| **`ActionRegistry.resolve` vs `ShellContext.command`** | Registry resolves/binds a command for a context. Shell context first consults `ShellCommandResolver`, then registry lookup. |
| **Global `Lookup` vs `ShellContext.lookup()`** | Global lookup provides application services. Shell context lookup is the per-shell service/profile/host view and may be a `ProxyLookup`. |
| **`.instance` vs `.ref` vs `.dynamic`** | Class-based behavior registration, action placement reference, and dynamic menu section respectively. |
| **`profiles` vs `visibleByDefault`** | Profiles control applicability. `visibleByDefault` controls initial visibility after applicability. Empty profile sets are inclusive. |
| **`WindowKind` vs `PaneRole.DETACHED`** | `WindowKind` classifies MAIN/FLOATING/CUSTOM windows. `PaneRole.DETACHED` is a Legacy pane role used by the tab implementation. |
| **`WindowClosePolicy`** | HIDE/REDOCK/CLOSE_CONTENT behavior for floating/custom windows. The 11-argument `WindowOptions` constructor and internal floating default use CLOSE_CONTENT; target default REDOCK is not yet the baseline default. |
| **`DockPolicySpec`** | Immutable predicate data already present in `api.shell`; empty sets are unrestricted. `DockPolicy.fromSpec` evaluates it with injectable identity resolvers. Production wiring and pointer integration remain target-only. |
| **`WindowActivation`** | Internal helper used by `DockWindow.show()` to call `show`, `toFront`, and `requestFocus` on the stage. |
| **`ExternalDrop`** | Internal neutral payload record adapted from a JavaFX drag event for testable routing. `ExternalDrop.from` and `FileDragAndDrop.localFilesFrom` are implementation details, not public API. |
| **Profile vs decoration** | Profile selects chrome/regions. Decoration is NATIVE/UNDECORATED and may override the selected profile. |
| **`show()` / `hide()` / `close()` / `redock()`** | `show` activates the stage. Hide preserves a live handle. Close is policy-dependent: HIDE remains managed/re-showable; REDOCK is floating-only and uses home/main fallback; CLOSE_CONTENT is the default. Main close remains a plain stage close. Explicit `redock(DockRequest)` moves a live floating window back into the dock. |
| **`rememberBounds`** | WindowOptions flag honored for custom windows in this baseline. Floating windows still use detached-pane layout persistence. |
| **Shell OVERLAY region vs `PresentationId.OVERLAY` vs `OverlayHost`** | Window chrome slot, dockable presentation id, and target anchored HUD host are three distinct concepts. Only the first two exist here. |
| **`ThemeToken` vs target `Theme`** | A token describes CSS defaults/metadata. Target `Theme`, `ThemeManager`, and `ThemeScope` do not exist here. |
| **`StatusAlignment.CENTER` vs `FILL`** | CENTER is deprecated; the renderer treats it as FILL. Baseline has no target status scopes. |
| **Malformed skip vs thrown error** | Annotation processors fail compilation. Runtime registries often log/skip a bad entry. Structural frame/DOCK/thread errors throw. |
| **Reason key vs exception** | Docking/drop rejection is a returned decision with a stable key. Invalid method state/arguments throw exceptions. |
| **Headless test vs real UI proof** | Headless Glass/software Prism proves scene/lifecycle logic, not native windows, monitors, or OS-level input. |
